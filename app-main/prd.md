PRD：安卓定时录音上传与结果推送工具
1. 文档信息
- 产品名称：定时录音助手
- 产品形态：Android APK
- 版本：V1.0
- 开发 IDE：Android Studio Panda 4 | 2025.3.4
- IDE 内部版本号：AI-253.32098.37.2534.15232325（构建日期：2026-04-18）
- JDK 运行时：OpenJDK 21.0.10（64-bit，随 Android Studio 内置）
- 目标用户：个人用户
- 部署方式：安卓客户端 + 已有阿里云服务器
- 支持系统：Android 10 及以上（minSdk 29，targetSdk / compileSdk 34）
- 网络要求：支持 Wi-Fi / 移动网络
- 文档类型：完整版 PRD

2. 产品背景
用户希望有一个可直接使用的安卓录音工具，能够按照预设时间段自动开始录音、自动结束录音，并在录音过程中按固定时长切片生成音频文件并上传到云端服务器，由服务器完成音频处理（如摘要生成、关键词/异常识别），再将处理结果返回到 App 中展示，并在识别到异常/关键词时立即通知用户。

该产品价值在于：

1. 自动化录音：无需手动开启关闭；
2. 后台稳定运行：支持开机启动、长期值守；
3. 云端处理闭环：录音上传、处理、回传结果；
4. 异常即时提醒：识别到关键词或异常后第一时间通知；
5. 可查看可追溯：本地文件、上传记录、处理结果、消息中心、日志诊断统一可查。

3. 产品目标
3.1 业务目标
- 提一款可直接安装使用的 Android 定时录音工具；
- 满足个人用户在固定时间段自动录音的需求；
- 支持音频自动切片并上传到阿里云服务器；
- 接收云端结构化 JSON 处理结果；
- 提供异常识别后的本地通知提醒；
- 实现录音、上传、处理、通知、查询的完整闭环。

3.2 用户目标
用户可以：
- 配置多个录音时间段；
- 查看当前是否在录音；
- 查看本地录音文件；
- 查看每个录音切片是否已上传；
- 查看云端返回的摘要/识别结果；
- 查看异常通知和历史消息；
- 在出现问题时查看诊断日志。

4. 用户画像
4.1 目标用户
个人用户，具备如下特征：
- 有规律性时间段录音需求；
- 希望手机自动执行任务，不想人工干预；
- 希望录音后自动上传分析；
- 对结果查看和异常提醒有需求；
- 可接受安装 APK 并进行权限授权。

4.2 典型使用场景
1. 用户每天在固定时间自动录音；
2. 录音按固定时长切片，例如每 1 分钟或 5 分钟一个文件；
3. 文件上传到阿里云服务器；
4. 服务器生成摘要、识别关键词或异常；
5. 出现异常后 App 立即弹出通知；
6. 用户后续可在消息中心和结果页查看详情。

7. 默认配置确认
以下配置已确认为 V1.0 默认方案：

1. 切片时长
- 默认：5 分钟
- 用户可在设置中调整为 1 分钟 / 5 分钟 / 10 分钟

2. 文件格式
- 默认格式：m4a/aac
- 理由：安卓原生支持好、文件体积小、上传更省流量
- V1.0 暂不支持其他格式（mp3/wav 后续版本可考虑）

3. 保留天数
- 默认：7 天
- 用户可在设置中调整为 1 / 3 / 7 / 15 / 30 天

4. 通知触发规则
- 客户端根据服务端返回 JSON 判断，满足以下任一条件即触发系统通知：
  - alertFlag 为 true
  - riskLevel 为 medium 或 high（枚举字符串，固定小写：low / medium / high，不做数值比较）
  - keywords 数组非空（length > 0）
- JSON 字段包含：fileId、fileName、status、summary、keywords、alertFlag、riskLevel、message、processedAt

5. 结果获取方式
- 采用客户端轮询方式
- 上传成功后，每隔 30 秒轮询一次结果接口
- 最多轮询 10 次（合计约 5 分钟），超时后标记为「结果获取失败」，用户可手动刷新
- 轮询间隔与最大次数可在设置中调整（V1.0 默认 30 秒 / 10 次）；若服务端处理常超过 5 分钟，建议调大后再验收
- 异常结果可通过服务端推送/长连接加快刷新（可选优化，非 V1.0 必做）

8. 用户流程
8.1 主流程
1. 用户首次安装 App
2. 用户授予录音、通知、前台服务等权限
3. 用户配置录音时间段
4. App 到达计划时间自动开始录音
5. 录音按固定时长切片
6. 切片文件落地到本地存储
7. App 自动上传切片到服务器
8. 服务器处理音频并返回结构化 JSON
9. App 展示处理结果
10. 若检测到关键词/异常，则立即通知用户
11. 文件按保留策略自动清理

8.2 异常流程
- 无网络：本地缓存待上传，恢复网络后自动补传
- 上传失败：自动重试，超过阈值进入失败队列
- App 被系统回收：依赖前台服务、开机自启、任务恢复机制
- 权限缺失：提示用户重新授权
- 电池优化限制：引导用户加入白名单
- 录音被占用：提示麦克风被其他应用占用

9. 功能需求详述
9.1 首页 / 效率大盘
功能说明
用户进入 App 后以「极低记录门槛」为核心：顶部搜索、中部时间线内容流、底部悬浮录音舱。录音进行态跳转至全屏录音页，不再在首页堆叠控制台卡片。

页面模块（自上而下）
- 全局搜索框：跨结果/上传/消息检索（V1.2 起支持实时过滤）
- 场景快捷横滑：即时速记、会议记录、课堂讲座、定时值守
- 今日值守任务摘要（有任务时展示）
- 统一时间线内容流：按时间倒序合并展示处理结果、上传记录、通知消息
- 底部悬浮输入舱：中央录音主按钮 + 文字快捷 + 更多抽屉
- 更多抽屉入口：录音任务、本地文件、消息中心、处理结果、诊断、关于

需求点
- 用户 2 步内进入录音（点录音 → 选场景 → 开始）
- 时间线卡片一眼扫到核心摘要
- 录音进行中自动进入全屏录音页
- 定时类场景引导至任务配置页，不盲目开录

9.2 录音任务列表
功能说明
用户可配置多个录音时间段，支持启用/停用。

需求点
- 新增录音任务
- 编辑录音任务
- 删除录音任务
- 启用/停用任务
- 支持多个时间段
- 展示示例：
- 09:00 - 12:00
- 14:00 - 18:00
- 默认按每日重复执行

字段设计
- 任务名称（可选）
- 开始时间
- 结束时间
- 是否启用
- 重复规则（V1.0 可默认每日）
- 音频格式（可选，如果开放）
- 切片时长
- 文件保留天数（全局或任务级）

规则校验
- 开始时间必须早于结束时间
- 不同任务的时间段不允许重叠（含边界重合，例如 09:00–12:00 与 12:00–14:00 视为重叠）
- 保存时若检测到重叠，弹窗提示并阻止保存
- 至少保留一个已启用的时间段，才能开启自动录音服务

9.3 录音执行模块
功能说明
系统在设定时间自动开始录音，到结束时间自动停止。录音过程中定时切片生成文件。

需求点
- 到点自动开始录音
- 到点自动停止录音
- 支持后台录音
- 支持前台服务保活
- 按固定时长切片
- 每个切片单独文件命名
- 录音中可显示实时状态

状态定义
- idle：空闲
- scheduled：已排程
- recording：录音中
- slicing：切片写入中
- uploading：上传中
- paused/error：异常状态

文件命名规范（V1.0）
- 格式：{deviceIdShort}_local_{yyyyMMdd}_{HHmmss}_{seq}.{format}
- deviceIdShort：deviceId 的前 8 位（见 14.0 环境与对接约定）
- seq：三位序号，从 001 起
- 示例：a1b2c3d4_local_20260522_090000_001.m4a

切片规则建议
- 每 5 分钟切片一次
- 任务结束时如不足 5 分钟，也生成最后一个切片
- 每个切片生成后立即进入上传队列

9.4 文件上传模块
功能说明
录音切片生成后自动上传到已有阿里云服务器。

需求点
- HTTPS 上传
- 支持分片文件逐个上传
- 支持上传队列
- 支持失败重试
- 支持断网缓存
- 支持网络恢复后自动补传
- 展示上传状态

上传状态
- 待上传
- 上传中
- 上传成功
- 上传失败
- 重试中

上传策略建议
- 录音切片生成后立即上传
- 若当前无网，先进入待上传队列
- 网络恢复自动重试
- 单文件最多重试 3 次
- 超过次数标记为失败，允许用户手动重传

9.5 云端处理结果模块
功能说明
服务器接收音频后进行摘要生成和关键词/异常识别，并返回结构化 JSON。App 负责接收、存储、展示。

展示内容
- 音频文件名
- 上传时间
- 处理状态
- 摘要内容
- 关键词列表
- 异常标记
- 风险等级
- 结果时间

处理状态
- 待处理
- 处理中
- 已完成
- 失败

JSON 建议结构
{
  "fileId": "abc123",
  "fileName": "a1b2c3d4_local_20260522_090000_001.m4a",
  "status": "completed",
  "summary": "本段录音主要讨论了今日工作安排与客户回访事项。",
  "keywords": ["客户", "投诉", "退款"],
  "alertFlag": true,
  "riskLevel": "high",
  "message": "检测到异常关键词：退款、投诉",
  "processedAt": "2026-05-22T09:06:30+08:00"
}

- App 冷启动时间 < 3 秒
- 单日持续运行稳定，无明显卡顿或崩溃

10.2 稳定性要求
- 支持开机自启

12. 安卓实现要求
12.1 后台运行策略
由于 Android 10+ 对后台行为限制严格，必须采用以下策略：

- 使用 Foreground Service（前台服务） 持续承载录音任务
- 常驻通知栏显示“录音服务运行中”
- 使用系统调度机制进行任务恢复
- 开机后恢复录音计划
- 引导用户关闭电池优化限制
- 根据厂商机型提供自启动白名单设置说明

12.2 定时策略
建议使用：
- AlarmManager + 前台服务
- 或 WorkManager 做恢复兜底
- 到达录音开始时间时拉起录音服务
- 到达结束时间时停止本次录音

14. 接口设计建议
你说服务器已有，所以这里我先给客户端对接接口建议，方便开发和联调。

14.0 环境与对接约定
- 客户端 SDK：minSdk 29（Android 10），targetSdk / compileSdk 34（与 tech_design.md 一致）
- 服务端 Base URL：在 App 设置中由用户或部署人员配置（如 https://your-domain.com），V1.0 不做云端自动发现
- 鉴权：V1.0 无账号体系；可选在设置中配置 API Key，请求头携带 Authorization: Bearer <apiKey>；未配置时仅传 deviceId，是否放行由服务端策略决定
- deviceId：首次启动生成 UUID 并持久化；上传接口必传；卸载重装后生成新 deviceId
- 隐私与合规：首次启动展示录音用途说明，用户确认后继续；关于/隐私页说明数据上传至用户配置的服务器、合法使用录音的责任由用户自行承担

14.1 文件上传接口
POST /api/audio/upload

请求：
- file
- fileName
- format
- startTime
- endTime
- duration
- deviceId
- localId

返回：

{
  "code": 0,
  "message": "success",
  "data": {
    "fileId": "abc123",
    "status": "uploaded"
  }
}

14.2 结果查询接口
GET /api/audio/result?fileId=abc123

返回（data 字段与 9.5 节 JSON 结构一致）：

{
  "code": 0,
  "message": "success",
  "data": {
    "fileId": "abc123",
    "fileName": "a1b2c3d4_local_20260522_090000_001.m4a",
    "status": "completed",
    "summary": "本段录音主要内容为……",
    "keywords": ["投诉", "退款"],
    "alertFlag": true,
    "riskLevel": "high",
    "message": "检测到异常关键词：退款、投诉",
    "processedAt": "2026-05-22T09:06:30+08:00"
  }
}

14.3 批量结果查询接口
POST /api/audio/result/batch

用途：
- 提高轮询效率
- 一次查询多个 fileId 结果

14.4 心跳/状态上报接口（可选）
POST /api/device/heartbeat

用于：
- 上报客户端状态
- 是否正在录音
- 待上传数量
- 异常信息

V1.0 可选。

16. 页面原型逻辑说明
16.1 首次启动
- 展示录音用途与隐私说明（数据上传至用户配置的服务器、合法使用责任等），用户确认后继续
- 请求录音权限
- 请求通知权限
- 引导开启电池优化白名单
- 引导开启自启动
- 可选：引导配置服务端 Base URL、API Key
- 进入首页

16.2 首页
漏斗式布局：
- 顶部：全局搜索 + 设置入口
- 中部：场景快捷横滑 + 今日值守摘要 + 时间线内容流
- 底部：悬浮录音舱（主录音 / 文字 / 更多）
- 更多抽屉：任务、文件、消息、结果、诊断、关于
- 底部 Tab 精简为：首页 / 文件 / 设置

16.2.1 录音准备页
- 顶部卖点文案（自动切片上传）
- 2×2 场景宫格：即时速记、会议记录、课堂讲座、定时值守

- 底部红色圆形开录按钮（需先选中可开录场景）
- 课堂/定时值守场景跳转任务列表

16.2.2 录音进行页
- 可编辑会话标题
- 中部拟人化状态文案占位（V2 接 ASR 转写）
- 声纹动画 + 有效录音计时
- 底栏：取消（二次确认）/ 暂停·继续 / 完成

16.3 任务页
- 顶部：新增任务按钮
- 列表：每个任务显示时间段+启用状态
- 点击进入编辑

16.4 结果详情页
- 摘要
- 关键词

17. 异常处理设计
17.1 录音异常
场景：
- 麦克风被占用
- 权限丢失
- 录音服务异常退出

处理：
- 记录日志
- 首页状态改为异常
- 发本地提醒
- 支持用户重启

17.2 上传异常
场景：
- 无网络
- 超时
- 服务器返回错误
- 文件不存在

处理：
- 自动重试
- 入失败队列
- 提示手动重传
- 日志记录

17.3 结果异常
场景：
- 文件上传成功但处理超时
- 返回 JSON 格式异常
- 查询不到 fileId

处理：
- 继续轮询指定次数
- 标记结果异常
- 用户可手动刷新

18. 验收标准
18.1 功能验收
1. 能新增多个录音时间段；
2. 到达开始时间后自动开始录音；
3. 到达结束时间后自动停止录音；
4. 录音可按固定时长切片生成文件；
5. 切片文件能自动上传；
6. 断网后文件可缓存，恢复网络后自动补传；
7. 可接收并展示服务器返回的 JSON 结果；
8. 命中关键词/异常时能弹出通知；
9. App 内可查看消息中心；
10. 可查看本地文件、上传状态、日志；
11. 开机后可自动恢复服务；
12. 文件可按保留天数自动清理。

18.2 性能验收
1. 连续运行 24 小时无严重崩溃；
2. 正常网络下上传成功率达到预期；
3. 定时任务误差控制在合理范围；
4. 后台运行时不影响基本可用性。

19. 风险与限制
1. 安卓后台限制
- 不同厂商对后台录音、自启动、定时唤起限制很大；
- 即便实现前台服务，也可能需要用户手动设置白名单。

2. 录音合规风险
- 涉及录音采集时，需明确用户自行承担合法合规使用责任；
- App 须在首次启动与关于/隐私页提供录音用途告知及隐私说明（见 14.0、16.1）。

3. 音频格式差异
- mp3 在部分原生录音实现中不如 m4a 稳定；
- wav 文件过大，不利于长期上传。

4. 服务端依赖
- 结果展示与提醒强依赖服务端返回 JSON 规范性和时效性。

20. V1.0 建议默认方案
为了尽快做成可直接使用版本，我建议 V1.0 默认如下：

- 开发环境：Android Studio Panda 4 | 2025.3.4（JDK 21）

- 通知方式：系统通知 + App 内消息中心
- 保留天数：7 天
- 网络策略：任意网络上传
- 后台策略：前台服务 + 开机自启 + 电池优化白名单引导
