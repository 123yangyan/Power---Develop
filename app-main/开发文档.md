> 版本：V1.1 · 稳定增强与体验补全

---

## 一、版本目标

V1.0 完成了核心录音闭环的 MVP 验证。V1.1 聚焦于**「让日常使用更顺手」**：

- 补全高频缺失功能（本地播放、手动录音）
- 修复已知功能缺口（WiFi 上传开关不生效、结果页无入口）
- 提升操作效率（批量重试、静音时段）
- 改善视觉体验（深色/浅色主题手动切换）

**规划周期**：6 周 / 3 个 Sprint
**任务总数**：12 个
**估算工期**：约 26 人·天

### T1 · 批量重试上传

**优先级**：P0 · **复杂度**：低 · **工期**：1 天 · **Sprint 1**

**目标**

在文件页一键重试所有失败/待上传文件，无需逐个点击。

**现状背景**

现有 `FilesViewModel.retryUpload(fileId)` 只支持单文件；`WorkScheduler.enqueuePendingUploads()` 已存在但未被 UI 调用。

**实现步骤**

1. 在 `FilesViewModel` 新增 `retryAllFailed()` 方法，调用 `workScheduler.enqueuePendingUploads()`
2. `FilesUiState.Success` 增加 `failedCount: Int` 字段
3. `FilesScreen` 在「失败/待上传文件数 > 1」时顶部展示 Callout Banner，内嵌「全部重试」按钮
4. 按钮触发后禁用防重复点击（1 秒内），Toast 提示「已加入重试队列」

**涉及文件**

| 文件 | 操作 | 说明 |
|------|------|------|
| `feature/files/.../FilesViewModel.kt` | 修改 | 新增 `retryAllFailed()` + `bulkRetryTriggered` 状态位 |
| `feature/files/.../FilesScreen.kt` | 修改 | 新增顶部 `FailedBanner` Composable，条件展示 |
| `feature/files/.../FilesUiState.kt` | 修改 | `Success` 内增加 `failedCount: Int` 字段 |

**验收标准**

- [ ] 存在 ≥2 条失败文件时，顶部 Banner 自动出现
- [ ] 点击「全部重试」后 Banner 消失，文件状态变为 RETRYING
- [ ] 无失败文件时 Banner 不展示

> ⚠️ 注意：`enqueuePendingUploads` 内部已有去重逻辑，注意避免重复入队

### T2 · 结果页导航入口补齐

**优先级**：P0 · **复杂度**：低 · **工期**：1 天 · **Sprint 1**

**目标**

补全孤立的 `results` 路由入口，让用户能从首页和文件页跳转到结果列表。

**现状背景**

`results` 路由已注册在 NavHost，但 `FilesScreen` 和 `HomeScreen` 均未调用 `navigate("results")`，导致结果页完全无法进入（**孤立路由**）。

**实现步骤**

1. `RecorderApp.kt`：给 `FilesRoute`、`HomeRoute` 传入 `onNavigateToResults: () -> Unit` 回调
2. `HomeScreen`：在「最近结果」卡片右上角加「查看全部」TextButton → `onNavigateToResults()`
3. `FilesScreen`：每条文件 Item 在 `processStatus == COMPLETED` 时显示「查看结果」按钮 → `onNavigateToResults()`
4. `ResultsRoute` 增加可选 `fileId` 参数，支持从文件详情直跳特定结果（后期补充）

**涉及文件**

| 文件 | 操作 | 说明 |
|------|------|------|
| `app/.../navigation/RecorderApp.kt` | 修改 | `FilesRoute`/`HomeRoute` 传入 `onNavigateToResults`，NavHost 内路由调用 |
| `feature/home/.../HomeScreen.kt` | 修改 | 最近结果区域添加「查看全部」入口 |
| `feature/files/.../FilesScreen.kt` | 修改 | `FileItem` 处理结果完成时显示跳转按钮 |

**验收标准**

- [ ] 首页最近结果区域可点击跳转到结果列表
- [ ] 文件列表中处理完成的文件可跳转到结果列表
- [ ] 结果页可通过 TopAppBar 返回上一页

> ⚠️ 建议与 T5（结果搜索）同期上线，避免结果页进入后体验过空

### T3 · 本地音频播放

**优先级**：P0 · **复杂度**：中 · **工期**：3 天 · **Sprint 1**

**目标**

在 App 内直接播放本地录音切片，提供播放/暂停/进度控制。

**现状背景**

`FilesScreen` 当前只展示文件元数据，无任何播放能力。文件存储在 `AudioFileEntity.filePath`，使用系统 `MediaPlayer` 即可读取。

**实现步骤**

1. 新建 `AudioPlayerController`，封装 `MediaPlayer` 生命周期：`prepare`、`start`、`pause`、`seekTo`、`release`
2. 使用 `StateFlow` 暴露 `PlayerState`（`IDLE/PREPARING/PLAYING/PAUSED/COMPLETED/ERROR`）和 `progressMs`/`durationMs`
3. 在 `FilesScreen` 每条 `FileItem` 底部增加折叠式播放条（点击文件展开），播放条含：进度 Slider、当前时间/总时长、播放/暂停按钮
4. 同一时刻只允许一个文件播放，切换时自动 `release` 前一个
5. 仅当 `filePath` 文件存在且 `uploadStatus != DELETED` 时显示播放按钮
6. `FilesViewModel` 注入 `AudioPlayerController`，暴露 `playerState` 到 UiState

**涉及文件**

| 文件 | 操作 | 说明 |
|------|------|------|
| `feature/files/.../AudioPlayerController.kt` | 新增 | `MediaPlayer` 封装，`StateFlow<PlayerState>`，进度 Flow |
| `feature/files/.../PlayerState.kt` | 新增 | `sealed class: Idle/Preparing/Playing/Paused/Completed/Error(msg)` |
| `feature/files/.../FilesViewModel.kt` | 修改 | 注入 `AudioPlayerController`，绑定 `playerState`；`onCleared()` 调用 `release()` |
| `feature/files/.../FilesScreen.kt` | 修改 | `FileItem` 增加 `PlaybackBar` Composable；Slider 绑定进度 |
| `feature/files/.../FilesUiState.kt` | 修改 | `Success` 增加 `playerState: PlayerState, playingFileId: Int?` |

**验收标准**

- [ ] 点击文件展开播放条，再次点击可折叠
- [ ] 播放/暂停按钮正常工作，进度条可拖拽跳转
- [ ] 切换文件播放时，上一个自动停止
- [ ] 文件不存在时播放按钮置灰且提示「文件已清理」

> ⚠️ **关键风险**：`MediaPlayer.prepare()` 为阻塞调用，必须在 `Dispatchers.IO` 上执行，避免 ANR；建议使用 `prepareAsync()` + `OnPreparedListener`

### T4 · 手动录音模式

**优先级**：P0 · **复杂度**：高 · **工期**：4 天 · **Sprint 1**

**目标**

首页一键启动/停止临时录音，不依赖预设时间段，录制完成后自动上传。

**现状背景**

`RecordService` 依赖 `taskId` 关联 `ScheduleTask`，手动模式需要一个虚拟「手动任务」。`RecordServiceController` 已有 `startRecording(taskId)` / `stopRecording(taskId)` 接口。

**实现步骤**

1. 约定 `taskId = 0` 为「手动任务」保留 ID，不存储到 `task_schedule` 表
2. `HomeViewModel` 新增 `startManualRecording()` / `stopManualRecording()`，调用 `RecordServiceController`
3. `HomeScreen` `RecordingHeroCard` 区域：空闲时显示「立即录音」按钮；录音中时显示「停止录音」按钮 + 计时器
4. `RecordService`：收到 `taskId = 0` 时跳过 `ScheduleTask` 查询，使用全局切片时长（DataStore），文件命名加 `manual` 标记
5. 手动录音文件存入 `audio_file` 表，`task_id = 0`，正常走上传流程
6. 并发处理：手动录音期间计划任务到达时，手动录音先停止并切片，计划任务正常启动

**涉及文件**

| 文件 | 操作 | 说明 |
|------|------|------|
| `feature/home/.../HomeScreen.kt` | 修改 | `RecordingHeroCard` 增加「立即录音/停止录音」按钮，录音中显示计时 |
| `feature/home/.../HomeViewModel.kt` | 修改 | 新增 `startManualRecording()` / `stopManualRecording()`；`isManualMode: Boolean` 状态 |
| `feature/home/.../HomeUiState.kt` | 修改 | `Success` 增加 `isManualMode: Boolean` |
| `sync/.../RecordService.kt` | 修改 | 处理 `taskId == 0` 分支，跳过 `ScheduleTask` 查询，`task_name` 显示「手动录音」 |
| `sync/.../RecordServiceController.kt` | 修改 | 新增 `startManualRecording()` / `stopManualRecording()` 便捷方法 |
| `core/model/.../AudioFile.kt` | 修改 | `isManualRecording: Boolean` 字段（便于文件列表区分来源，可选） |

**验收标准**

- [ ] 首页空闲状态下可见「立即录音」按钮
- [ ] 点击后状态变为「录音中」，按钮变为「停止录音」
- [ ] 停止后文件出现在文件列表，来源标记「手动」
- [ ] 手动录音期间计划任务到达时，手动录音停止并切片后计划任务正常启动

> ⚠️ **最高风险任务**：必须在 `RecordService` 内用 `AtomicBoolean` 做互斥锁，防止两个 `MediaRecorder` 同时启动导致崩溃。开发前需先设计并发控制方案。

### T5 · 结果关键词搜索

**优先级**：P1 · **复杂度**：低 · **工期**：2 天 · **Sprint 2**

3. `ResultsScreen` 顶部增加 `SearchBar`（M3 SearchBar 或 OutlinedTextField），支持 clear
4. 无结果时显示已有 `EmptyState` 组件

**涉及文件**

| 文件 | 操作 | 说明 |
|------|------|------|
| `feature/results/.../ResultsViewModel.kt` | 修改 | 新增 `_query StateFlow`，`combine` 过滤逻辑 |
| `feature/results/.../ResultsUiState.kt` | 修改 | `Success` 增加 `query: String, filteredResults` 字段 |
| `feature/results/.../ResultsScreen.kt` | 修改 | 顶部增加搜索框，绑定 `onQueryChange → viewModel.setQuery()` |

**验收标准**

- [ ] 输入关键词后列表实时过滤，匹配 `summary` 或 `keywords` 中任意项
- [ ] 清空搜索框恢复全量列表
- [ ] 无匹配时展示 EmptyState

> 注意：关键词搜索建议忽略大小写；`keywords` 为 JSON 数组，需反序列化后再搜索

### T7 · 录音质量档位

**优先级**：P1 · **复杂度**：低 · **工期**：2 天 · **Sprint 2**

**目标**

在设置中支持选择音频比特率（32 / 64 / 128 kbps），平衡录音质量与文件大小/流量。

**现状背景**

`RecordService` 中 `MediaRecorder` 使用固定 `bitRate`，DataStore 尚无此偏好项。设置页已有切片时长选择器，可参照同样的交互模式。

**实现步骤**

1. `core/model` 新建 `AudioBitrate.kt`（枚举：`KBPS_32 / KBPS_64 / KBPS_128`，各含 `bitsPerSecond: Int` 和 `estimateMbPerHour: Float`）
2. `UserPreferences` 增加 `audioBitrate: AudioBitrate = AudioBitrate.KBPS_64`
3. `RecordService` 初始化 `MediaRecorder` 时调用 `setAudioEncodingBitRate(prefs.audioBitrate.bps)`
4. `SettingsScreen` 新增「录音质量」分组，每档下方显示预估文件大小（32kbps ≈ 14MB/h，64kbps ≈ 28MB/h，128kbps ≈ 56MB/h）

**涉及文件**

| 文件 | 操作 | 说明 |
|------|------|------|
| `core/model/.../AudioBitrate.kt` | 新增 | `enum class AudioBitrate(bps: Int, label: String, estimateMbPerHour: Float)` |
| `core/datastore/.../UserPreferences.kt` | 修改 | 增加 `audioBitrate: AudioBitrate = AudioBitrate.KBPS_64` |
| `sync/.../RecordService.kt` | 修改 | 初始化 `MediaRecorder` 时调用 `setAudioEncodingBitRate(prefs.audioBitrate.bps)` |
| `feature/settings/.../SettingsScreen.kt` | 修改 | 新增「录音质量」选择区，含文件大小估算文字 |
| `feature/settings/.../SettingsViewModel.kt` | 修改 | 新增 `updateAudioBitrate()` |

**验收标准**

- [ ] 设置中可选 32 / 64 / 128 kbps，默认 64
- [ ] 每档显示预估文件大小
- [ ] 新录制文件的比特率符合所选设置
- [ ] 设置页说明「修改仅对新建录音生效」

### T8 · 通知静音时段

**优先级**：P1 · **复杂度**：中 · **工期**：2 天 · **Sprint 2**

**目标**

配置免打扰时间段（如 22:00–07:00），在此时间段内异常通知静默推送，不弹系统通知。

**现状背景**

`AlertNotifier` 是发通知的唯一出口，在此处加时间判断即可。`UserPreferences` 需增加静音时段配置项。

**实现步骤**

1. `UserPreferences` 增加 `quietModeEnabled: Boolean`（默认 false）、`quietStartMinutes: Int`（默认 1320 = 22×60）、`quietEndMinutes: Int`（默认 420 = 7×60）
2. `AlertNotifier.sendAlert()` 中：若 `quietModeEnabled = true`，则判断当前时间是否在静音区间（需处理跨午夜逻辑）
3. `SettingsScreen` 新增「免打扰时段」分组：开关 + 开始/结束时间选择器（M3 TimePicker）
4. 静音期间的通知仍存入 `message_center` 表，消息中心可正常查看，只是不推系统通知

**涉及文件**

| 文件 | 操作 | 说明 |
|------|------|------|
| `core/datastore/.../UserPreferences.kt` | 修改 | 增加 `quietModeEnabled, quietStartMinutes, quietEndMinutes` |
| `sync/.../AlertNotifier.kt` | 修改 | `sendAlert()` 开头加静音时段判断逻辑 |
| `feature/settings/.../SettingsScreen.kt` | 修改 | 新增免打扰时段 UI 分组（开关 + 时间选择器） |
| `feature/settings/.../SettingsViewModel.kt` | 修改 | 新增 `updateQuietMode()` / `updateQuietHours()` |

**验收标准**

- [ ] 开启静音时段并设置 22:00–07:00 后，此时间段内不弹系统通知
- [ ] 异常结果仍写入消息中心，可正常查看
- [ ] 时间段设置重启后持久化

> ⚠️ 跨午夜判断逻辑（如 22:00–07:00）需专门编写工具函数并添加单元测试覆盖边界情况：
> `当前分钟 >= quietStart 或 当前分钟 <= quietEnd` 时处于静音期

### T9 · 文件导出分享

**优先级**：P2 · **复杂度**：低 · **工期**：2 天 · **Sprint 3**

**目标**

支持将本地录音文件分享至微信、邮件等第三方应用。

**现状背景**

Android 标准 `Intent.ACTION_SEND` + `FileProvider` 即可实现；需在 Manifest 声明 FileProvider 并提供 `res/xml/file_paths.xml`。

**实现步骤**

1. `AndroidManifest.xml` 增加 `FileProvider` provider 声明（`authority = com.timedrecorder.fileprovider`）
2. `res/xml/file_paths.xml`：声明 `external-files-path` 指向录音文件目录
3. `FileItem` 增加「分享」IconButton（share icon），仅当 `filePath` 文件存在时可用
4. `FilesViewModel` 新增 `buildShareIntent(fileId)` → 通过 `FileProvider.getUriForFile()` 获取 `content://` URI → 返回 Intent
5. UI 层使用 `LocalContext.current.startActivity(shareIntent)` 触发系统分享菜单

**涉及文件**

| 文件 | 操作 | 说明 |
|------|------|------|
| `app/src/main/AndroidManifest.xml` | 修改 | 新增 `FileProvider <provider>` 声明 |
| `app/src/main/res/xml/file_paths.xml` | 新增 | 声明可分享的文件路径范围 |
| `feature/files/.../FilesScreen.kt` | 修改 | `FileItem` 增加分享 IconButton |
| `feature/files/.../FilesViewModel.kt` | 修改 | 新增 `buildShareIntent(fileId): Intent` |

**验收标准**

- [ ] 点击分享按钮弹出系统分享菜单
- [ ] 可成功分享至微信文件传输助手并收到文件
- [ ] 文件已被清理时分享按钮置灰

> ⚠️ Android 7+ 必须用 `FileProvider`，直接传 `file://` URI 会崩溃（`FileUriExposedException`）

### T10 · WiFi 专属上传功能修复

**优先级**：P1 · **复杂度**：低 · **工期**：1 天 · **Sprint 2**

**目标**

修复「仅 WiFi 上传」开关实际不生效的存量 Bug。

**现状背景**

`WorkScheduler.networkConstraints()` 目前使用 `NetworkType.CONNECTED`，未读取 `wifiOnlyUpload` 偏好。`DataStore` 和 `SettingsUI` 均已有此开关，但后台未接入，开关形同虚设。

**实现步骤**

1. `WorkScheduler` 注入 `UserPreferencesDataSource`
2. `networkConstraints()` 中读取 `wifiOnlyUpload`：`true` → `NetworkType.UNMETERED`；`false` → `NetworkType.CONNECTED`

**涉及文件**

| 文件 | 操作 | 说明 |
|------|------|------|
| `sync/.../WorkScheduler.kt` | 修改 | 注入 `UserPreferencesDataSource`，`networkConstraints()` 读取 `wifiOnlyUpload` 偏好 |

**验收标准**

- [ ] 开启「仅 WiFi 上传」后，切换到移动数据时上传任务不执行
- [ ] 切换回 WiFi 后任务自动恢复上传

> 注意：WorkManager 约束变更只对新加入的任务生效，已有 pending 任务需重新 enqueue 才能应用新约束

### T11 · 桌面快捷小组件

**优先级**：P2 · **复杂度**：高 · **工期**：4 天 · **Sprint 3**

**目标**

提供 Android 桌面小组件，显示当前录音状态、今日任务数、未读消息数。

**现状背景**

需实现 `AppWidgetProvider`（推荐使用 Glance API，可用 Compose 语法写 Widget UI）。`minSdk = 29`，Glance 最低 API 26，兼容无问题。

**实现步骤**

1. `app/build.gradle.kts` 增加依赖：`androidx.glance:glance-appwidget`
2. 创建 `RecorderWidget.kt`（`GlanceAppWidget` 子类），展示：录音状态圆点 + 文字、今日任务数、未读消息数
3. 创建 `RecorderWidgetReceiver.kt`（`GlanceAppWidgetReceiver` 子类）
4. `AndroidManifest.xml` 注册 WidgetReceiver + meta-data 指向 `widget_info.xml`
5. `res/xml/widget_info.xml`：定义尺寸（2×1 格）、`updatePeriodMillis`（最小 1,800,000 = 30 分钟）
6. 数据刷新：`RecordingStateHolder` 状态变化时调用 `GlanceAppWidgetManager.updateIf<>()`

**涉及文件**

| 文件 | 操作 | 说明 |
|------|------|------|
| `app/.../widget/RecorderWidget.kt` | 新增 | `GlanceAppWidget`：录音状态、今日任务、未读消息展示 |
| `app/.../widget/RecorderWidgetReceiver.kt` | 新增 | `GlanceAppWidgetReceiver` 注册入口 |
| `app/src/main/res/xml/widget_info.xml` | 新增 | Widget 元数据：尺寸、更新频率 |
| `app/src/main/AndroidManifest.xml` | 修改 | 注册 `RecorderWidgetReceiver` + `AppWidgetProvider` meta-data |
| `app/build.gradle.kts` | 修改 | 新增 `glance-appwidget` 依赖 |

**验收标准**

- [ ] 在桌面长按可添加「定时录音助手」小组件
- [ ] 组件显示当前录音状态（录音中/空闲）
- [ ] 录音状态变化后 30 秒内组件更新

> ⚠️ Widget 内不能使用标准 Compose 组件，只能用 Glance 提供的 `GlanceText`/`GlanceRow` 等组件子集，开发前务必查阅 Glance 文档

### T12 · 首页卡片自定义排序

**优先级**：P2 · **复杂度**：中 · **工期**：2 天 · **Sprint 3**

**目标**

允许用户在设置中调整首页各功能卡片的显示顺序，并支持隐藏不需要的卡片。

**现状背景**

`HomeScreen` 目前硬编码了 5 个卡片区域的顺序（录音状态、今日任务、最近上传、最近结果、最近消息），可通过 DataStore 持久化顺序配置。

**实现步骤**

1. `core/model` 新建 `HomeCardId.kt` 枚举（`RECORDING_STATUS / TODAY_SCHEDULE / RECENT_UPLOADS / RECENT_RESULTS / RECENT_MESSAGES`）
2. `UserPreferences` 增加 `homeCardOrder: List<HomeCardId>`（默认顺序）
3. `HomeViewModel` 读取 `homeCardOrder`，对卡片列表排序后传入 UiState
4. `HomeScreen` 根据 `orderedCards` 动态渲染卡片（不再硬编码顺序）
5. `SettingsScreen` 新增「首页卡片」分组，使用「上移/下移」按钮（降低复杂度）

**涉及文件**

| 文件 | 操作 | 说明 |

| `core/model/.../HomeCardId.kt` | 新增 | `enum class HomeCardId { RECORDING_STATUS, TODAY_SCHEDULE, ... }` |
| `core/datastore/.../UserPreferences.kt` | 修改 | 增加 `homeCardOrder: List<HomeCardId>` |
| `feature/home/.../HomeViewModel.kt` | 修改 | 注入偏好，排序卡片列表 |
| `feature/home/.../HomeScreen.kt` | 修改 | 卡片渲染改为遍历 `orderedCards` |
| `feature/settings/.../SettingsScreen.kt` | 修改 | 新增首页卡片排序 UI（上移/下移按钮） |
| `feature/settings/.../SettingsViewModel.kt` | 修改 | 新增 `moveCardUp()` / `moveCardDown()` / `toggleCardVisible()` |

**验收标准**

- [ ] 设置页可调整首页卡片顺序
- [ ] 调整后首页立即按新顺序展示
- [ ] 重启 App 后顺序持久化

## 七、风险清单

| 等级 | 关联任务 | 风险描述 | 缓解措施 |
|------|----------|----------|----------|
| 高 | T4 手动录音 | 手动录音与计划任务并发，两个 `MediaRecorder` 同时启动会崩溃 | `RecordService` 内用 `AtomicBoolean` 互斥锁；手动录音收到计划任务信号后先 finalizeSlice 再让位 |
| 高 | T3 本地播放 | `MediaPlayer.prepare()` 为阻塞调用，主线程调用会 ANR | 在 `Dispatchers.IO` 上调用；使用 `prepareAsync()` + `OnPreparedListener` |
| 中 | T11 桌面组件 | Glance Widget 组件子集有限，标准 Compose 效果无法直接用 | 提前阅读 Glance 文档；使用 `GlanceText`/`GlanceRow` 等专用组件 |
| 中 | T6 主题切换 | SplashScreen 期间主题未加载，可能短暂白屏 | 用 `isLoading` 状态控制内容显示时机 |
| 中 | T8 静音时段 | 跨午夜时段判断逻辑（22:00–07:00）容易出边界 Bug | 单独封装 `isInQuietHours()` 工具函数 + 单元测试 |
| 低 | T9 文件分享 | `file://` URI 在 Android 7+ 会崩溃 | 严格使用 `FileProvider.getUriForFile()`，authority 与 Manifest 保持一致 |
| 低 | T7 录音质量 | 32kbps 低质量用户可能误以为是 Bug | 设置页标注适用场景；默认 64kbps 平衡 |
