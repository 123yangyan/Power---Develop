# PC 身心交织看板（云端全量同步方案 · 优化版）

基于原 Cursor 方案优化：5 表 → **13 表全覆盖**、单页 → **4 标签页看板**、新增数据保留策略与降采样。

---

## 对原方案的优化点

| 原方案 | 优化后 |
|--------|--------|
| 只同步 5 张表（hr/skinTemp/ppi/acc/mood） | **扩展到 13 张表全覆盖** |
| 缺少睡眠-情绪关联分析 | **新增睡眠阶段图 + 次日情绪对照** |
| 看板只有单页叠加曲线 | **多标签页：实时曲线 / 睡眠 / 活动 / 情绪日历** |
| 未明确数据保留策略 | **服务端自动降采样：原始数据保留 30 天，聚合数据永久** |
| 未考虑大量时序数据索引 | **复合索引 (device_id, ts) + 降采样加速查询** |

---

## 总体架构

```
┌─────────────────┐     HTTP/JSON      ┌──────────────────────┐     HTTPS      ┌──────────────┐
│  Android App     │ ──────────────────▶│  FastAPI Server       │ ◀───────────── │  PC Browser  │
│  (13 Room 表)    │   WorkManager      │  (Docker, 阿里云)     │   ECharts      │  看板页面     │
│  SyncManager     │   周期同步          │  SQLite + Redis       │               │  /dashboard  │
└─────────────────┘                    │  Nginx 反代           │               └──────────────┘
                                        └──────────────────────┘
```

**原地扩展**：不新建项目，在现有 `server/` 上加 API 路由和看板页面，Android 侧补 SyncManager 实现。

## Part 1 — Server 扩展（FastAPI + SQLite）

### 1.1 数据模型（`app/vitals_models.py`）

新增 13 张时序数据表，统一列约定：

```python
# 公共列
device_id: String(64)   indexed
source: String(32)      # "LIVE_STREAM" | "OFFLINE_SYNC" | "USER_INPUT"
client_row_id: String(64)  # Android 端 row id
ts: BigInteger           # 时间戳 ms
created_at: DateTime     # 服务端接收时间

# 唯一约束: (device_id, source, client_row_id) — 幂等上报
```

**A 组：实时 BLE 流（4 表）** — 高频数据，服务端保留 30 天后自动降采样

| 服务端表名 | 对应 Android 表 | 指标列 |
|-----------|----------------|--------|
| `hr_samples` | `hr_samples` | bpm, rr_ms |
| `skin_temp_samples` | `skin_temp_samples` | temperature_c |

### 1.2 数据 API（`app/vitals_api.py`）

挂载到 `main.py`，所有接口复用 `Depends(verify_api_key)`。

**批量上报**：

```
POST /api/vitals/batch
Body: {
  "deviceId": "xxx",
  "source": "LIVE_STREAM",
  "table": "hr_samples",
  "rows": [
    {
      "clientRowId": "123",       // Android 端主键 id（字符串化）
      "ts": 1718000000000,
      "bpm": 72,
      "rrMs": 820
    },
    ...
  ]
}
Response: { "code": 0, "message": "success", "data": { "inserted": 45, "skipped": 3 } }
```

- 每批最多 500 行
- 幂等 upsert：`(device_id, source, client_row_id)` 唯一约束 + INSERT OR REPLACE

**查询接口**：

| 端点 | 用途 |
|------|------|
| `GET /api/dashboard/devices` | 返回有数据的 deviceId 列表 + 最新活跃时间 |
| `GET /api/dashboard/series?device=&from=&to=&tables=&maxPoints=` | 按时间窗返回多表原始数据（降采样） |
| `GET /api/dashboard/summary?device=&date=` | 某天的聚合摘要：步数、卡路里、睡眠、情绪数 |
| `GET /api/dashboard/mood-calendar?device=&year=&month=` | 月度情绪日历热力图数据 |

### 1.3 看板页面（`app/static/dashboard.html`）

单页应用，CDN 引入 ECharts 5.x，4 个标签页：

**标签页 1：身心交织曲线**（对齐 Android `MindBodySplineChart`）
- HR（红色）+ 皮肤温度（橙色）+ HRV/RMSSD（紫色）三 Y 轴叠加曲线
- 运动强度色带（活动分钟背景着色）
- 心情事件散点标注（悬停显示日记摘要、coord、关联 HR）
- 时间范围预设：1h / 6h / 24h / 3d / 7d
- 设备下拉选择

**标签页 2：睡眠分析**
- 睡眠阶段分布图（深睡/浅睡/REM/清醒 — 从 `sleepWakePhasesJson` 解析）
- 睡眠时长趋势（柱状图，7/14/30 天）
- 睡眠质量 vs 次日情绪对照表

**标签页 3：运动活动**
- 步数日趋势（柱状图）
- 卡路里组成（堆叠柱状图：活动/训练/BMR）
- 活动分钟分布（热力图：横轴=日，纵轴=小时）

**标签页 4：情绪日历**
- 月度情绪热力图（横轴=日，纵轴=周，颜色=valence coord_x）
- 点击某天展开当日日记卡片列表
- 情绪角色(roleId) 统计饼图

### 1.4 数据保留与降采样

- 高频数据（hr/ppi/skin_temp）保留 30 天原始数据
- 每 24h：对 30 天前数据计算小时级 avg/min/max，写入 `*_hourly` 聚合表，删除原始行
- 聚合表结构：`device_id, hour_ts, avg_bpm, min_bpm, max_bpm, sample_count`
- 低频数据（activity_day、sleep、nightly_recharge、mood）永久保留原始数据

### 2.3 改造 SyncManager

**当前**：`SyncManager` 只接收 `HrRepository`，`syncOnce()` 是 TODO 占位。

**改造后**：接收 `AppStorage` 全部门面 + `SyncPreferences` + `SyncApiClient`：

```
syncOnce() 流程：
  1. 检查 syncEnabled
  2. 遍历 9 个 SyncableDao<Long> 仓库
     （hr, skinTemp, acc, ppi, hr247, ppi247, skinTemp247, activityMinute, mood）
     → getUnsynced(500) → 映射 DTO → POST /api/vitals/batch
     → 成功 markSynced(ids) / 失败 markFailed(ids)
     → 循环直到无 PENDING
  3. 遍历 4 个 String-key DAO
     （activityDay, nightlyRecharge, sleep, training）
     → 同上流程，用 String key 标记
  4. 返回 SyncResult(uploaded, failed, skipped)
```

每批 500 行。`source` 字段：LIVE_STREAM 表的行使用 `"${table}:${id}"` 格式作为 `clientRowId`。

### 2.4 WorkManager 调度（`MindBodyApplication.kt`）

```kotlin
SyncWorker.schedulePeriodic(
    context = this,
    intervalHours = 2,
    constraints = Constraints.Builder()
        .setRequiredNetworkType(NetworkType.CONNECTED)
        .setRequiresBatteryNotLow(true)
        .build()
)
```

`onTerminate()` 中触发一次 `flushAll()` + 同步（可选）。

### 2.5 开发者控制面板（`DeviceScreen.kt`）
