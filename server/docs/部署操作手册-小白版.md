# 定时录音助手 — 小白部署操作手册

> 适用对象：第一次部署阿里云服务器的用户  
> 预计总耗时：1～2 小时（含控制台配置）  
> 你的服务器信息：ECS 杭州 `120.26.204.190`，2核8G，Alibaba Cloud Linux 3

---

## 一、先搞清楚我们要做什么

整体流程可以记成一句话：

**手机 App 把录音上传到 ECS → ECS 存到 OSS → 百炼 AI 分析 → App 轮询拿结果**

你需要完成三块工作：

| 顺序 | 在哪里做 | 做什么 |
|------|----------|--------|
| 1 | 阿里云网页控制台 | 配置 OSS、RAM 角色、百炼 Key、安全组 |
| 2 | SSH 连上 ECS | 上传代码、安装 Docker、启动服务 |
| 3 | 手机 App | 填服务器地址和 API Key，测试上传 |

## 三、第一步：阿里云控制台配置（网页操作）

> 全部在浏览器打开：https://www.aliyun.com/ 登录后操作

### 3.1 创建或确认 OSS 存储桶（Bucket）

**目的**：存放手机上传的录音文件。

1. 顶部搜索栏输入 **「对象存储 OSS」**，进入控制台
2. 左侧点击 **「Bucket 列表」** → **「创建 Bucket」**
3. 按下面填写（其他保持默认即可）：

| 配置项 | 填什么 | 为什么 |
|--------|--------|--------|
| Bucket 名称 | 全局唯一英文名，如 `my-recorder-audio-2026` | 记下来，后面要写进 `.env` |
| 地域 | **华东1（杭州）** | 必须和 ECS 同地域，走内网更快更省 |
| 存储类型 | 标准存储 | 你的资源包就是标准存储 |
| 读写权限 | **私有** | 不公开，更安全 |

4. 创建成功后，点进这个 Bucket
5. 左侧 **「基础设置」** → **「生命周期」** → **「创建规则」**：

| 配置项 | 填什么 |
|--------|--------|
| 规则名称 | `auto-delete-audio` |
| 前缀 | `audio/` |
| 文件时间 | 距最后修改时间 **30** 天 |
| 操作 | 删除文件 |

> 作用：防止 40GB 被录音占满。

---

### 3.2 创建 RAM 角色（让 ECS 免密码访问 OSS）

**目的**：服务器上传/读取 OSS 时，不需要把 AccessKey 写在代码里。

#### 3.2.1 创建自定义权限策略

1. 顶部搜索 **「访问控制 RAM」** → 左侧 **「权限管理」** → **「策略」**
2. 点击 **「创建策略」** → 选择 **「脚本编辑」**
3. 策略名称填：`TimedRecorderOSSPolicy`
4. 把下面 JSON 粘贴进去，**把 `YOUR_BUCKET_NAME` 换成你的 Bucket 名**：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:PutObject",
        "oss:GetObject",
        "oss:DeleteObject",
        "oss:ListObjects",
        "oss:ListObjectsV2"
      ],
      "Resource": [
        "acs:oss:*:*:YOUR_BUCKET_NAME",
        "acs:oss:*:*:YOUR_BUCKET_NAME/*"
      ]
    }
  ]
}
```

5. 点击 **「确定」** 创建

#### 3.2.2 创建 RAM 角色

1. RAM 控制台 → **「身份管理」** → **「角色」** → **「创建角色」**
2. 信任主体选：**「阿里云服务」** → 下一步
3. 角色类型选：**「普通服务角色」**
4. 角色名称填：`TimedRecorderECSRole`
5. 选择刚才建的策略 `TimedRecorderOSSPolicy` → 创建

#### 3.2.3 把角色绑定到你的 ECS

1. 搜索 **「云服务器 ECS」** → **「实例」**
2. 找到实例 **「大模型」**（IP `120.26.204.190`）
3. 点击实例 ID 进入详情
4. 左侧或顶部找到 **「实例详情」** → **「实例元数据」** 或 **「更多」→「实例状态」→「绑定/更换实例 RAM 角色」**
5. 选择 `TimedRecorderECSRole` → 确定

---

### 3.3 获取百炼 API Key

**目的**：调用阿里云语音识别（Fun-ASR）和通义千问做摘要。

1. 搜索 **「大模型服务平台百炼」** 或 **「模型服务灵积」**
2. 开通服务（按页面提示，新用户通常有免费额度）
3. 进入 **「API Key 管理」** → **「创建 API Key」**
4. 复制 Key（sk-e2e7a255216a4e1a8a7fae2b087b35a7），保存到记事本

> 注意：Key 只显示一次，丢了要重新创建。

---

### 3.4 配置安全组（开放 443 端口）

**目的**：让手机能通过 HTTPS 访问你的 API。

1. ECS 控制台 → 你的实例 → **「安全组」** 标签
2. 点击安全组 ID 进入规则页
3. **「入方向」** → **「手动添加」**，添加两条规则：

| 端口 | 协议 | 授权对象 | 说明 |
|------|------|----------|------|
| 443 | TCP | 0.0.0.0/0 | App 访问 HTTPS |
| 22 | TCP | 你的家庭/公司公网 IP/32 | SSH 登录（更安全） |

> 不知道自己的公网 IP？浏览器搜索「我的 IP」，把显示的地址后面加 `/32`，例如 `123.45.67.89/32`  
> 如果暂时图方便，22 端口也可以填 `0.0.0.0/0`，但安全性较差。

4. （可选）再加一条 80 端口 TCP `0.0.0.0/0`，用于 HTTP 自动跳转到 HTTPS

## 四、第二步：用 SSH 连接服务器

### 4.1 Windows 上打开终端

1. 按 `Win + R`，输入 `powershell`，回车
2. 测试能否 ping 通服务器：

```powershell
ping 120.26.204.190
```

有回复说明网络通。

### 4.2 SSH 登录

```powershell
ssh root@120.26.204.190
```

- 第一次会问 `Are you sure you want to continue connecting?`，输入 `yes` 回车
- 然后输入 ECS 的 root 密码（输入时屏幕不显示字符，正常现象）
- 看到类似 `[root@xxx ~]#` 就说明登录成功了

> 如果提示 `ssh` 不是命令：Windows 10/11 可在「设置 → 应用 → 可选功能」里安装 **OpenSSH 客户端**。

## 五、第三步：把 server 代码上传到 ECS

你在 Windows 上的代码路径大概是：

```
D:\OneDrive\Desktop\test\owner\server
```

### 方法 A：用 scp 上传（推荐）

**先不要关闭 SSH 窗口**，再新开一个 PowerShell 窗口，执行：

```powershell
scp -r "D:\OneDrive\Desktop\test\owner\server" root@120.26.204.190:/opt/timedrecorder
```

- 会要求输入 root 密码
- 上传完成后，服务器上代码在 `/opt/timedrecorder`

### 方法 B：没有 scp 时

1. 把 `server` 文件夹打成 zip
2. 用 WinSCP（免费软件）连接 `120.26.204.190`，上传到 `/opt/timedrecorder`
3. SSH 里解压：

```bash
cd /opt
unzip timedrecorder.zip -d timedrecorder
```

## 六、第四步：在服务器上配置环境变量

SSH 登录状态下执行：

```bash
cd /opt/timedrecorder
cp .env.example .env
```

编辑配置文件（二选一）：

**方式 1 — 用 nano 编辑器（简单）：**

```bash
nano .env
```

**方式 2 — 用 vim：**

```bash
vim .env
```

把内容改成类似下面（**换成你自己的真实值**）：

```env
OSS_REGION=cn-hangzhou
OSS_BUCKET=my-recorder-audio-2026
OSS_RAM_ROLE_NAME=TimedRecorderECSRole
OSS_INTERNAL_ENDPOINT=true

DASHSCOPE_API_KEY=sk-你的百炼Key

API_KEY=MyRecorder2026!

DATABASE_URL=sqlite:////data/recorder.db
REDIS_URL=redis://redis:6379/0

SIGNED_URL_EXPIRES_SECONDS=3600
ASR_MODEL=fun-asr
LLM_MODEL=qwen-plus
```

保存退出：
- nano：按 `Ctrl+O` 回车保存，`Ctrl+X` 退出
- vim：按 `Esc`，输入 `:wq` 回车

## 十一、常见问题排查

### 问题 1：`curl` 连不上 / 超时

- 检查安全组是否放了 **443** 端口
- 检查 `docker compose ps` 里 nginx 是否在运行
- 执行 `docker compose logs nginx` 看报错

### 问题 2：上传返回 401

- App 里的 API Key 和服务器 `.env` 的 `API_KEY` 不一致
- 或请求头没带 `Authorization: Bearer xxx`

### 问题 3：上传成功但一直 pending / processing

```bash
docker compose logs -f worker
```

常见原因：
- `DASHSCOPE_API_KEY` 错误或没开通 Fun-ASR
- RAM 角色未绑定，OSS 上传失败
- OSS Bucket 名称写错

### 问题 4：App 提示 SSL / 证书错误

- 必须用 **Debug 构建**（项目已配置自签证书信任）
- Base URL 必须是 `https://` 开头，不要加 `:443`
- 不要用 `http://`

### 问题 5：OSS 上传失败

检查清单：
- [ ] Bucket 在 **杭州**
- [ ] `.env` 里 `OSS_BUCKET` 名称正确
- [ ] RAM 角色 `TimedRecorderECSRole` 已绑定 ECS
- [ ] 策略里的 Bucket 名和实际一致

### 问题 6：修改配置后如何重启

```bash
cd /opt/timedrecorder
# 改了 .env 后
docker compose down
docker compose up -d --build
```
